# 第一部分：D1 · 从裸机到一台能用的 Linux 服务器

## 1.1 装 VMware、建虚拟机

**做了什么**：在 Windows 上装虚拟机软件，用 Ubuntu 的 ISO 文件"虚拟"出一台电脑。

**为什么需要它**：
你只有一台物理笔记本，但项目需要**同时跑多台机器**（后面域控要 2 台、监控要 2-3 台、Ansible 要 2 台）。虚拟化就是"用软件模拟出多台电脑"——一台物理机，变出 N 台逻辑机器，各自独立装系统、独立 IP，互不干扰。

**现实中的联系（这块很重要）**：
- 企业里的服务器，**99% 都是虚拟机**：VMware ESXi、KVM、阿里云 ECS、腾讯云 CVM，本质全是虚拟机
- 你现在用的 VMware Workstation，和企业机房里的 ESXi 是同一家公司的产品、同一套逻辑
- 所以你在虚拟机里练的所有东西，和真实工作环境**完全一致**，不存在"练的和干的不一样"

**为什么新手必须用虚拟机练（三个不可替代的好处）**：
1. **快照回滚**：装崩了、配错了，一键回到 10 分钟前（真实物理机重装要半天）
2. **随时克隆**：需要第二台机器？复制一份虚拟机就行，几分钟
3. **零成本试错**：随便搞坏，反正不是公司的生产环境

**面试可以这么说**：
> "我的实验环境是 VMware 虚拟机，和企业里的 ESXi、云服务器是同一套虚拟化逻辑。用虚拟机做实验可以快照回滚、随时克隆多台，试错成本为零。"

## 1.2 装 Ubuntu Server（那几个关键选项为什么这么选）

### 为什么选 Server 版，而不是带桌面的 Desktop 版？

- **服务器不需要图形界面**：机房里的服务器没有显示器，全是远程命令行操作
- **省资源**：桌面环境要吃掉 1-2GB 内存和不少 CPU，这些资源应该留给业务
- **减少攻击面**：图形界面意味着更多软件、更多漏洞、更多要打的补丁
- **便于自动化**：命令行操作可以写成脚本，图形界面没法自动化

**面试点**：被问"为什么服务器不装桌面"——答这三点（省资源、减攻击面、可自动化），比答"因为大家都这么干"强得多。

### 为什么语言必须选 English？

这是手册里特意埋的坑，两个原因：

1. **终端和日志不会乱码**：中文环境下，某些命令的输出、报错信息会出现编码问题，排查故障时你会看不懂报错，白白浪费几小时
2. **报错信息要能搜到答案**：运维排障的核心技能是"把报错复制到搜索引擎"。英文报错全球都有人遇到过、有答案；中文报错基本搜不到

**现实联系**：所有生产环境服务器，清一色 English。这不是崇洋，是工程实践——英文报错能谷歌到解决方案，这是硬需求。

### 为什么建普通用户 jasper，而不是直接用 root？

- **root 是超级管理员**，拥有"做任何事"的权限，包括删掉整个系统（`rm -rf /` 的传说就是 root 干的）
- **最小权限原则**：日常用普通用户干活，需要管理员权限时临时用 `sudo` 借一下
- **可追溯**：每个操作都能对应到具体的人（企业里多人共用服务器，用谁的账号操作一目了然）

**现实联系**：企业服务器**全部禁止 root 直接 SSH 登录**（sshd 配置里 `PermitRootLogin no`），运维人员都是用个人账号登录后再 sudo 提权。这是安全基线，也是等保要求。

### 为什么机器名设成 sv01？

- 机房里几十上百台机器，**靠 IP 记不住，靠名字区分**
- 监控告警发出来，显示的是主机名（"sv01 磁盘 85%"），不是 IP
- 日志里也记录主机名，排查问题时靠它定位是哪台机器

**命名规范**：`sv01` = server 01。真实企业里常见命名方式：
- 按角色：`web-01`、`db-01`、`redis-01`
- 按环境：`prod-web-01`、`test-web-01`
- 按机房/机柜：大公司会精确到位置

## 1.3 第一组命令（每行都是为什么）

```bash
sudo apt update && sudo apt upgrade -y
```

### sudo 是什么
你登录的是普通用户 jasper，很多操作（装软件、改系统配置）需要管理员权限。`sudo` = "用管理员身份执行这一条命令"，执行完权限就收回，不会一直保持管理员状态——这就是最小权限原则的落地。

### apt update 和 apt upgrade 的区别（面试高频题）

| 命令 | 干什么 | 大白话比喻 |
|---|---|---|
| `apt update` | 刷新软件目录（有哪些软件、什么版本） | 刷新外卖菜单 |
| `apt upgrade` | 按新目录把已装软件升级 | 按新菜单把旧菜换掉 |

**为什么要先更新**：刚装好的系统，软件版本可能带着已知漏洞。安全补丁是运维的底线——真实工作中，接手一台新服务器，第一步就是打补丁。

**现实联系**：企业里会有"补丁管理"制度（每月补丁日、漏洞扫描、紧急补丁流程）。你现在手工做一次，理解的是这个制度的底层动作。

### 为什么要配国内镜像源（你踩的第一个坑）

**软件源是什么**：apt 从哪个服务器下载软件的地址。默认是 `archive.ubuntu.com`（在国外）。

**你遇到的问题**：换成清华源后报 `403 Forbidden`——这是 HTTP 状态码，意思是"服务器拒绝给你这个文件"（镜像同步问题或路径写法问题）。最后换成阿里源解决。

**现实联系**：企业内网会搭**私有镜像源**（Nexus、Harbor、内部 apt/yum 源），目的有三个：
1. 快（内网千兆，比公网快几十倍）
2. 安全可控（只放行审核过的软件版本）
3. 省带宽（几百台服务器不用都去公网下载）

你换国内源，和这个思路是同一回事。

```bash
ip a
```

### 为什么 IP 这么重要

IP 是服务器的"门牌号"。没有 IP，你就找不到这台机器——SSH 连不上、监控采不到、服务访问不了。

**现实联系**：运维交接服务器，第一句话永远是"IP 多少"。排查任何网络问题，第一步都是确认 IP、网段、网关、DNS。

```bash
hostnamectl
```

查看/修改机器名。你用它确认了 hostname 是 sv01——这是系统身份标识，也是监控和日志里的身份。

# 第二部分：D2 · 让"能连上"变成"安全地连上"

## 2.0 先理解：SSH 到底是什么（为什么需要它）

服务器在机房或云上，你不可能每次操作都跑到机器前接个显示器和键盘。**SSH 就是一条加密的远程登录隧道**——你在隧道这头敲命令，服务器在那头执行，全程加密。

### 对比 Telnet（为什么现在没人用 Telnet 了）

| | Telnet | SSH |
|---|---|---|
| 传输方式 | **明文**（密码在网上裸奔） | 全程加密 |
| 端口 | 23 | **22** |
| 现状 | 基本淘汰，只在老设备调试用 | 行业标准 |

用抓包工具（你简历里的 Wireshark）能看到 Telnet 的密码明文，这就是为什么它被淘汰。

**大白话**：SSH 是你和服务器之间的一条加密隧道，所有操作都在这条隧道里走，外面的人看不到内容。

---

## 2.1 启动 SSH 服务（你遇到的 inactive dead）

你装系统时勾了 OpenSSH server，但服务显示 `inactive (dead)`——**包装上了，但服务没启动**。

### systemctl 三兄弟（运维最常用的命令，没有之一）

| 命令 | 效果 | 大白话 |
|---|---|---|
| `systemctl start ssh` | 现在启动 | 现在把灯打开 |
| `systemctl enable ssh` | 设开机自启 | 设成每天天亮自动开灯 |
| `systemctl enable --now ssh` | 两个都要 | 现在开灯 + 以后自动开 |
| `systemctl status ssh` | 看状态 | 灯现在是开着还是关着 |

**这就是运维的日常**：服务器上所有服务（Nginx、MySQL、Zabbix、Redis...）都靠 systemctl 管理。启动、停止、重启、看状态、设开机自启——这几条命令你这辈子会敲几万次。

### 状态含义速查
- `active (running)` = 正常跑着
- `inactive (dead)` = 装了但没跑（你遇到的）
- `failed` = 启动失败了（要看日志排查）

---

## 2.2 生成密钥对（非对称加密，大白话版）

### 对称加密 vs 非对称加密

- **对称加密**：加密和解密用同一把钥匙（像家门钥匙，能开就能锁）
- **非对称加密**：有一对钥匙——公钥和私钥

**公钥和私钥的关系**（这是理解 D2 的关键）：
- **公钥 = 一把锁**：可以随便给人，谁都能用这把锁把东西锁起来
- **私钥 = 唯一的钥匙**：绝不能给别人，只有它能打开对应那把锁
- 用公钥锁上的东西，**只有对应的私钥能打开**，连拿公钥的人自己都打不开

### 为什么选 ed25519

老教程教你用 `ssh-keygen -t rsa -b 4096`（RSA 4096 位），现在推荐 **ed25519**：更现代的算法，密钥更短（一行就能放下）、更快、安全性更高。这是当前的行业最佳实践。

### 为什么不设密码短语

生成时提示"输入密码短语"，你一路回车跳过了。练习阶段这样方便（否则每次登录都要再输一次短语）。**生产环境建议设**——万一私钥文件被偷，还有第二道锁。

---

## 2.3 传公钥到服务器（那条管道命令在干什么）

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh jasper@192.168.207.128 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

这条命令看起来复杂，拆成三段就懂了：

| 片段 | 干什么 | 大白话 |
|---|---|---|
| `type 公钥文件` | 读出你公钥的内容 | 把锁拿出来看看 |
| `\|`（管道符） | 把前面命令的输出，变成后面命令的输入 | 接力棒，交给下一条命令 |
| `ssh user@ip "命令"` | 远程到服务器上执行引号里的命令 | 跑到服务器上干活 |

引号里的命令做了两件事：
1. `mkdir -p ~/.ssh` = 建 .ssh 目录
2. `cat >> ~/.ssh/authorized_keys` = 把传过来的公钥内容追加进这个文件

### authorized_keys 是什么

服务器上的**"允许登录的公钥白名单"**——里面每一个公钥，都对应一把被信任的锁。你的公钥进去了，服务器就认你这把锁。

### 为什么必须 chmod 700 / 600

OpenSSH 有个"洁癖"设计：如果 `.ssh` 目录或 `authorized_keys` 文件权限太松（比如其他用户也能写入），它会**拒绝使用密钥登录**。

**为什么这么设计**：如果别人能改你的 authorized_keys，他就能把自己的公钥加进去，从而登录你的账号。所以 SSH 强制要求"只有你自己能写"。这是安全设计，不是 bug。

**现实联系**：企业里给几百台服务器批量放公钥，靠的是 Ansible 或自动化运维平台（就是模块 H 要学的）——原理和你手工放一模一样，只是批量化和可重复。

---

## 2.4 免密登录（为什么它不是"不安全"，而是"更安全"）

你看到"直接进去了，也没输密码"，觉得奇怪——**这正是密钥登录成功的表现**。

### 免密 ≠ 没有验证

不是"服务器不验证你了"，而是**密钥在替你证明身份**。完整过程就是上面那张图的五步：

1. 你的电脑说"我要用 XX 密钥登录"
2. 服务器查白名单：这个公钥在名单里 → 继续
3. 服务器用这个公钥加密一段随机数，发给你（挑战）
4. 你的电脑用私钥解开，把结果回传（应答）
5. 服务器验证结果对 → 放行

### 为什么这比密码安全得多

| | 密码登录 | 密钥登录 |
|---|---|---|
| 密码/密钥是否上网传输 | **要传**（可能被截获） | **不传**（私钥永不出本地） |
| 能否被暴力破解 | 能（黑客每秒试几千个密码） | 不能（要算到宇宙毁灭） |
| 泄露风险 | 服务器被拖库就泄露 | 服务器上的公钥本来就是公开的，泄露也没用 |

**关键洞察**：私钥从未离开你的电脑，网络上传输的只是一段"数学证明"。这就是为什么密钥登录更安全。

### Permission denied (publickey) 是什么意思

服务器说："我只接受密钥登录，而你没提供对的密钥。"——这正是你最后想要的效果（密码登录被拒绝）。

---

## 2.5 关闭密码登录（你踩的第二个坑，最有价值的一个）

### 为什么要禁密码

互联网上每分钟都有机器人在扫描开放 22 端口的服务器，然后**暴力破解密码**（每秒试几千次）。只要你的密码不够强，迟早被攻破。禁掉密码登录，相当于把这扇门彻底焊死——只有持有私钥的人能进。

**现实中的安全基线**（企业服务器标准做法，全都要做）：
1. 禁用密码登录（你现在做的）
2. 禁止 root 直接登录（`PermitRootLogin no`）
3. 改 SSH 端口（从 22 改成别的，减少扫描噪音）——有争议，但很多公司做
4. 装 fail2ban（多次失败自动封 IP）
5. 用 VPN/堡垒机跳板，不直接暴露 SSH 到公网

### 你踩的坑：sshd_config.d 的 Include 优先级（重点！）

你的操作明明在 `/etc/ssh/sshd_config` 末尾加了 `PasswordAuthentication no`，但 `sshd -T` 仍然显示 `yes`。原因是：

1. Ubuntu 24.04 的主配置文件里有这一行：`Include /etc/ssh/sshd_config.d/*.conf`
2. sshd 解析配置时，会**把 Include 的文件内容先展开读进来**
3. sshd 的规则是 **first match wins**（同一个配置项，第一个读到的值生效，后面的忽略）
4. 而 `/etc/ssh/sshd_config.d/50-cloud-init.conf`（云初始化工具留下的）里有 `PasswordAuthentication yes`
5. 它是"第一个"，所以你主文件末尾的 `no` 成了"第二个"，**被忽略**

### sshd -T 是什么（这个命令救了你）

打印 sshd **实际生效的**完整配置。它比"看文件内容"可靠 100 倍——因为文件里写了什么，和服务实际读到的，可能不是一回事（就是你这个坑）。

**这条经验的价值（面试加分项）**：
> "改完 SSH 配置，我不用看文件确认，而是用 `sshd -T` 打印服务实际生效的值来验证——因为 Ubuntu 24.04 有 `sshd_config.d/` 的 Include 机制，cloud-init 留下的配置会优先于主文件，只看文件内容会误判。"

**这个坑，很多工作一两年的运维都不一定知道**。你今天亲手踩过、亲手解决，面试讲出来就是差异化的。

## 2.6 验证环节（为什么"失败"才证明成功）

```powershell
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no jasper@192.168.207.128
```

**这条命令在干什么**：用 `-o` 参数强制指定"只用密码认证、禁用密钥认证"，去尝试登录。

**期望结果**：`Permission denied (publickey).` —— 被拒绝。

**为什么"失败"才是成功**：这是一种**反向验证思维**——想证明某个功能被关掉了，就去试着用它，它应该失败。如果它还让你登进去，说明没关掉（就像你第一次测试时那样，密码登录成功了 = 配置没生效）。

这种"用测试证明配置生效"的思维，是运维的核心素养：**不是配完就算完，而是验证过才算完**。这和后面 Zabbix 项目里"故意写满磁盘验证告警真的会响"是同一种思维。

# 第四部分：面试怎么讲这两天的成果（60 秒版）

被问"你做过什么"或"讲讲你的实验环境"，可以用这段：

> "我自己搭了一台 Linux 服务器做练习。从装 Ubuntu Server 开始，配好网络和主机名，打完系统补丁；然后配了 SSH 密钥登录并关闭密码认证——私钥留本地、公钥放服务器，密码不再上网传输，安全性比密码登录高很多。过程中踩过一个坑：Ubuntu 24.04 的 sshd 会优先加载 `sshd_config.d/` 下的配置，cloud-init 留下的文件里写着允许密码登录，导致我在主配置里改的不生效。我最后用 `sshd -T` 打印服务实际生效的配置才定位到，然后把那个文件清理掉才真正生效。这次经历让我养成一个习惯：改完配置不看文件，看服务实际读到的值。"

**这段话为什么有力**：
1. 讲清楚了"做了什么"（装系统→配网络→打补丁→密钥登录→禁密码）
2. 讲清楚了"为什么"（安全性对比）
3. **讲了一个真实的坑 + 排查过程 + 沉淀的方法论**（这是面试官最想听的，因为它证明你是真做过，不是背的）

# 第五部分：你踩的三个坑，面试反而是加分项

很多初学者怕"出错"，但在运维这个岗位上，**踩过坑并解决过的人，比从没踩过坑的人值钱**——因为真实工作就是不断处理意外。

| 你踩的坑 | 背后学到的 | 面试价值 |
|---|---|---|
| 清华源 403 Forbidden | 软件源机制、HTTP 状态码、镜像同步 | 证明你会排查依赖下载问题（新人常见问题） |
| sshd_config.d 优先级覆盖 | Include 机制、first match 规则、`sshd -T` 验真 | **高价值**——很多人工作一两年都不知道 |
| sed 替换没匹配上 | 配置文件格式差异（前导空格、注释写法） | 证明你理解"配置不是改了就生效，要验证" |

**讲坑的正确姿势**：不要只说"我遇到了一个错误"，要说"我遇到了什么现象 → 我怎么定位 → 根因是什么 → 我怎么解决 → 我沉淀了什么习惯"。这个五段式，就是运维排查的标准叙事。

# 附录：命令速查表（每条 + 白话解释）

| 命令 | 白话解释 |
|---|---|
| `sudo` | 用管理员身份执行这一条命令 |
| `apt update` | 刷新软件目录（不装东西） |
| `apt upgrade -y` | 按新目录升级已装软件（-y = 不问直接干） |
| `ip a` | 看本机 IP 地址（服务器的门牌号） |
| `hostnamectl` | 看/改机器名 |
| `systemctl start 服务` | 现在启动服务 |
| `systemctl enable 服务` | 设开机自动启动 |
| `systemctl enable --now 服务` | 现在启动 + 开机自启（最常用） |
| `systemctl status 服务` | 看服务状态 |
| `systemctl restart 服务` | 重启服务（改完配置后） |
| `ss -tlnp \| grep :22` | 看 22 端口有没有在监听 |
| `ssh-keygen -t ed25519` | 生成密钥对（公钥+私钥） |
| `ssh 用户@IP` | 远程登录服务器 |
| `sshd -T` | 打印 sshd 实际生效的全部配置 |
| `sshd -t` | 校验配置文件语法（无输出=通过） |
| `grep -v 关键词 文件` | 输出"不含该关键词"的所有行 |
| `\|`（管道） | 把前面命令的输出，交给后面命令当输入 |
| `>` | 把输出写到文件（覆盖） |
| `>>` | 把输出追加到文件末尾 |
| `tee -a 文件` | 输出到屏幕的同时追加进文件（配合 sudo 用） |
