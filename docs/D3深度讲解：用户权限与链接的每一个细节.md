# D3 深度讲解：用户、权限与链接的每一个细节

> 配套：行动指南 D3（用户与权限）
> 特点：本报告嵌入了你今天**实际跑出的每一条输出**来讲解，不是通用教程——你看到的是"你的机器上的真实数据"该怎么读。

---

## 开篇：D3 在学什么

一句话：**理解 Linux 里"谁能对什么文件做什么"**。

这是"最小权限原则"的落地。D1 让服务器能跑起来，D2 让你能安全远程登录，D3 解决的是——**服务器上有多个人、多个程序时，怎么保证每个人/每个程序只能碰它该碰的东西。**

三个部分层层递进：

| 部分 | 核心问题 | 对应能力 |
|---|---|---|
| 建运维账号 | 谁可以登录、能做什么 | 身份与授权 |
| 权限体系 | 谁能读/写/执行哪个文件 | 访问控制 |
| inode 与链接 | 文件的"身份证"与"别名" | 文件系统底层理解 |

# 第一部分：建运维账号

## 1.1 为什么企业要给运维单独建账号

三个真实原因（不是教科书套话）：

1. **可追溯（审计要求）**：服务器上每个操作要能对应到具体的人。多人共用 root，删了库查不出是谁干的——这在金融、政企是重大事故。
2. **可控权（最小权限）**：需要什么给什么。如果一个账号只需要看日志，就绝不给它改配置的权限。
3. **安全基线（合规要求）**：等保 2.0、ISO27001 都明确要求"禁用 root 直接登录、一人一账号"。你投的政企驻场岗，上岗第一件事就是领一个个人账号。

**现实对照**：你 D1 建的 jasper 是"安装时建的初始账号"，D3 建的 ops 模拟"团队共用的运维账号"。真实企业里两者都有，但都**不用 root 直接干活**。

## 1.2 三条命令，逐个参数讲透

### `sudo useradd -m -s /bin/bash ops`

| 参数 | 含义 | 不写会怎样 |
|---|---|---|
| `-m` | 顺便创建家目录 `/home/ops` | 账号能建，但没家目录，登录后无处落脚 |
| `-s /bin/bash` | 指定登录后的 shell 是 bash | 默认是 `/bin/sh`（功能简陋，没命令补全、没历史记录） |
| `ops` | 用户名 | — |

**shell 是什么**：你登录后看到的那个"能敲命令的界面"就是 shell。bash 是最常用的一种，功能齐全。如果没指定，用户可能被分配到 `/bin/sh`，用起来很难受。

### `sudo passwd ops`

给 ops 设密码。密码**不显示**（连星号都没有），输两遍确认。

**运维常识**：Linux 里输入密码永远不回显，这是防"肩窥"（旁边有人看你屏幕能数出密码长度）。新手常以为"键盘坏了"。

### `sudo usermod -aG sudo ops`

| 参数 | 含义 |
|---|---|
| `-G` | 指定**附加组** |
| `-a` | **append（追加）**——加到组里，而不是替换 |
| `sudo` | 组名（Ubuntu 里 sudo 组成员可以用 sudo 提权） |

> ⚠️ **`-a` 绝对不能漏**：不加 `-a` 的话，`-G` 会**覆盖**用户原有的所有附加组。用户可能因此丢掉其他权限，极端情况下把自己锁在系统外。这是 Linux 运维的经典事故之一。

### 为什么是"加进 sudo 组"，而不是"把 root 密码告诉他"

| 做法 | 问题 |
|---|---|
| 把 root 密码给运维 | 无法追溯（不知道是谁在操作）、无法收回（改密码要通知所有人）、权限过大（误操作直接毁系统） |
| **加进 sudo 组** | 每次提权输**自己的密码**、所有 sudo 操作记入日志（`/var/log/auth.log`）、随时可以移出组收回权限 |

## 1.3 你的验证输出（逐行解读）

```
jasper@sv01:~$ whoami
jasper                          ← 起点：确认自己在 jasper 账号

jasper@sv01:~$ su - ops
Password:                       ← 输入 ops 的密码（不回显）
ops@sv01:~$                     ← 提示符变了：已切到 ops

ops@sv01:~$ sudo whoami
[sudo] password for ops:        ← 输 ops 自己的密码（不是 jasper 的！）
root                            ← ✅ 核心验证通过

ops@sv01:~$ groups
ops sudo                        ← ✅ ops 确实在 sudo 组里

ops@sv01:~$ exit
logout
jasper@sv01:~$                  ← 干净退回
```

### 三个易错点（你今天踩过两个）

| 你踩的 | 现象 | 正解 |
|---|---|---|
| `su -ops`（缺空格） | `su: invalid option -- 'o'`——`-ops` 被当成参数 `-o` `-p` `-s` | **`su - ops`**（横杠和用户名之间必须有空格） |
| `sudo - ops` | `sudo: -: command not found` | `sudo` 后面直接跟要执行的命令，如 `sudo whoami` |
| 在 jasper 下测 sudo | 输出 root，但只证明 jasper 有权限 | **必须切到目标账号再测**，才是在验证"ops 有没有 sudo" |

**为什么 `su -` 的横杠很重要**：
- `su ops` = 切换用户，但**保留原用户的环境变量**（工作目录、PATH 等）
- `su - ops` = 切换用户并**加载该用户的完整登录环境**（进自己的家目录、加载自己的配置）

运维习惯用 `su -`，因为环境干净、不会串味。

# 第二部分：权限体系（面试必考）

## 2.1 你的实际输出逐列拆解

```
drwxr-x---  4  jasper  jasper  4096  Sep  3 08:22  jasper
drwxr-x---  2  ops     ops     4096  Sep  3 08:48  ops
```

拆第一个字段 `drwxr-x---`：

```
d  rwx  r-x  ---
│   │    │    │
│   │    │    └── 其他用户（others）：---  无权限
│   │    └─────── 属组成员（group）：r-x  能读、能进
│   └──────────── 属主本人（user） ：rwx  读、写、进
└──────────────── 文件类型：d = 目录
```

后面字段依次是：**链接数 → 属主 → 属组 → 大小 → 修改时间 → 名称**。

## 2.2 文件类型位（第一个字符）

| 字符 | 含义 | 例子 |
|---|---|---|
| `-` | 普通文件 | 文本文件、脚本、二进制 |
| `d` | 目录 | `/home/jasper` |
| `l` | 软链接 | 你建的 softlink.txt |
| `c` | 字符设备 | 键盘、终端 |
| `b` | 块设备 | 硬盘 `/dev/sda` |
| `s` | 套接字 | 进程间通信 |
| `p` | 管道 | 进程间通信 |

## 2.3 rwx 的含义（对文件和目录**不同**——面试必考）

| 权限 | 对**文件** | 对**目录** |
|---|---|---|
| **r** (读) | 能看内容（`cat`） | 能列出里面有什么（`ls`） |
| **w** (写) | 能改内容 | 能**在目录里新建/删除文件** |
| **x** (执行) | 能当程序跑 | 能**进入**目录（`cd`） |

> ⭐ **面试官最爱的追问**："目录的 x 权限是什么意思？"
> 答：**能不能 cd 进去**。很多人答成"执行目录"——直接暴露没真正理解。
>
> 补充考点：只有 r 没有 x 的目录，能 `ls` 看到文件名，但**进不去也读不了内容**（会报 Permission denied）。

## 2.4 数字表示法：r=4，w=2，x=1

一组内相加：

```
rwx = 4+2+1 = 7
r-x = 4+0+1 = 5
rw- = 4+2+0 = 6
--- = 0+0+0 = 0
```

### 常见组合速查（背下来，面试直接写）

| 数字 | 权限串 | 典型用途 |
|---|---|---|
| **755** | rwxr-xr-x | 网站目录、可执行程序（其他人可读可执行） |
| **750** | rwxr-x--- | **你的家目录**（其他人完全进不去） |
| **644** | rw-r--r-- | 普通文件、配置文件 |
| **700** | rwx------ | `.ssh` 目录（只有自己能进） |
| **600** | rw------- | 私钥文件 `id_ed25519`（只有自己能读写） |

## 2.5 你的家目录为什么是 750 而不是 755（重要，你今天发现的）

| | 权限 | 其他用户能做什么 |
|---|---|---|
| 老版 Ubuntu（755） | `drwxr-xr-x` | 能**进你的家目录、看到你有哪些文件**（隐私泄露） |
| **24.04 默认（750）** | `drwxr-x---` | **完全进不去** |

**Ubuntu 从 21.10 起把家目录默认权限收紧为 750**，这是官方的安全加固。

> ⚠️ 所以：**不要执行 `chmod 755 /home/ops`**。那是基于老版本的旧教程，在 24.04 上执行它会把一个 750 的私密目录**降级**成 755，反而降低隐私保护。手册里这一步我已经删除并加了警告。

## 2.6 与 D2 的呼应：为什么 .ssh 必须 700/600

现在你能理解 D2 遇到的那个"权限洁癖"了：

| 文件 | 权限 | 如果放松会怎样 |
|---|---|---|
| `~/.ssh` | 700 | 其他用户能进你的 .ssh 目录 |
| `authorized_keys` | 600 | **其他用户能把自己的公钥塞进你的白名单 → 能登录你的账号** |
| `id_ed25519`（私钥） | 600 | 其他用户能**偷走你的私钥** |

OpenSSH 强制检查这些权限，不合规就拒绝使用密钥——这是**纵深防御**设计，不是 bug。

## 2.7 chmod / chown 用法

```bash
chmod 755 文件名              # 数字法
chmod u+x 文件名              # 符号法：给属主(u)加执行(x)权限
chmod -R 755 目录名           # 递归改整个目录（谨慎！）
sudo chown ops:ops 文件名     # 改属主和属组
sudo chgrp ops 文件名         # 只改属组
```

**符号法里的字母**：`u`=属主(user)，`g`=属组(group)，`o`=其他(others)，`a`=全部(all)；`+`加权限，`-`减权限，`=`设为。

**运维警告**：`chmod -R 777` 是新手最危险的冲动操作——等于把系统大门敞开。任何正规环境都不会这么做。

# 第三部分：inode 与软硬链接（面试高频）

## 3.1 inode 是什么

**一句话**：inode（index node）是 Linux 给每个文件发的**身份证号**。

### 技术定义

一个文件在 Linux 里由两部分组成：

| 部分 | 存在哪 | 内容 |
|---|---|---|
| **文件内容（数据）** | 磁盘的数据区 | 你写进去的字节 |
| **元信息（metadata）** | **inode** | 权限、属主、大小、时间戳、数据块在磁盘上的位置 |

**关键洞察**：**文件名不在 inode 里**。文件名只是目录里的一条"映射记录"（文件名 → inode 号）。所以：
- 一个 inode 可以有**多个文件名**（这就是硬链接）
- 改名（`mv`）不改变 inode，只改目录里的映射
- 删文件（`rm`）只是删掉一条映射记录

### 比喻（记住这个就够了）

| Linux | 比喻 |
|---|---|
| **inode** | 一个人的身份证号（唯一、终身不变） |
| **文件名** | 这个人的名字/外号（可以有多个） |
| **硬链接** | 给同一个人又起个外号——两个名字指向同一个人 |
| **rm** | 撕掉一个名字标签；只要还有别的名字贴着，人（数据）就还在 |
| **软链接** | 一张写着"他家地址"的纸条；人搬走了，纸条就废了 |

## 3.2 你的实验输出逐行解读

```
400473 -rw-rw-r-- 2 jasper jasper 13 Sep  3 08:56 /home/jasper/hardlink.txt
400475 lrwxrwxrwx 1 jasper jasper 21 Sep  3 08:56 /home/jasper/softlink.txt -> /home/jasper/test.txt
400473 -rw-rw-r-- 2 jasper jasper 13 Sep  3 08:56 /home/jasper/test.txt
```

| 观察点 | 数据 | 说明 |
|---|---|---|
| **inode 号** | test.txt 与 hardlink.txt **同为 400473** | ⭐ 硬链接铁证：他俩是同一个 inode 的两个名字 |
| | softlink.txt 是 **400475** | 软链接是独立的新文件 |
| **链接数**（第 2 列） | 硬链接是 **2** | 有 2 个文件名指向这个 inode |
| | 软链接是 **1** | 软链接自己独立 |
| **类型位** | `lrwxrwxrwx` 的 **`l`** | link，软链接 |
| **软链接权限** | 显示 777 | **这个权限位无意义**——实际能否访问取决于它指向的目标 |
| **软链接大小** | **21 字节** | 正好是路径 `/home/jasper/test.txt` 的字符数——**它存的就是一个路径字符串** |
| **箭头** | `-> /home/jasper/test.txt` | 明确告诉你指向哪 |

## 3.3 删源验证：你的输出说明了什么

```
rm ~/test.txt                      ← 删掉"其中一个名字"
cat ~/hardlink.txt → yunweishiyan  ← ✅ 内容还在！
cat ~/softlink.txt → No such file or directory  ← ❌ 失效
```

**结论**：

| | 删源后 | 原因 |
|---|---|---|
| 硬链接 | **照样能读** | inode 还有另一个名字指着，数据没被释放 |
| 软链接 | **失效报错** | 它存的路径指向的文件没了 |

**深层理解**：Linux 的"删除"本质是"解除一个文件名与 inode 的关联"。只有当**链接数归零**且**没有进程打开它**时，数据块才真正被释放。

## 3.4 面试高频题（就从这里来的）

**"我删了个 20G 的日志文件，磁盘空间没释放，为什么？"**

**答**：因为你删的只是一个"文件名"。如果有**进程还打开着这个文件**（比如 Nginx 还在往那个已删除的日志句柄里写），inode 仍被引用，数据块就不会释放。

**排查**：
```bash
lsof | grep deleted        # 找出"已删除但仍被进程占用"的文件
df -h                      # 看磁盘占用
```

**正确处理**：不要 `rm` 正在被写入的日志，应该**清空**：
```bash
> /var/log/nginx/access.log        # 截断为 0 字节，inode 不变，进程继续正常写
```

> 这是运维经典故障，面试出现率很高。能答出"进程持有已删除文件的句柄"的候选人，明显比只会 `df -h` 的高一个档次。

## 3.5 软硬链接的现实用途

| 场景 | 用法 | 例子 |
|---|---|---|
| **版本切换** | 软链接指向当前版本，升级时改指向 | `/usr/bin/python` → `python3.12`，装新版本只需改链接 |
| **程序升级回滚** | 软链指向 `app-v2.1`，出问题改回 `app-v2.0` | 秒级回滚，不用重新部署 |
| **日志路径映射** | 把应用日志软链到统一目录 | 便于集中采集 |
| 硬链接 | 用得少（不能跨分区、不能链目录） | 某些备份场景（同一份数据多个名字，省空间） |

# 第四部分：D3 的现实图景

## 企业里账号权限怎么管（你投的岗位会碰到）

| 层级 | 做法 | 目的 |
|---|---|---|
| **身份** | 一人一账号，禁止共享 | 可追溯 |
| **授权** | 按角色分（开发只读、运维可 sudo、DBA 管数据库） | 最小权限 |
| **提权** | sudo + 个人密码，全程记日志 | 可审计 |
| **登录** | 禁 root 直登、禁密码、走堡垒机 | 防入侵 |
| **审计** | 堡垒机录屏、命令审计、定期权限复核 | 合规（等保） |

**等保 2.0 三级要求**（政企岗必知，面试提到很加分）：
- **身份鉴别**：一人一账号、密码复杂度、登录失败锁定
- **访问控制**：按最小权限授权、默认拒绝
- **安全审计**：记录谁在什么时候做了什么，日志留存 ≥6 个月

## 权限最小化的日常落地

| 对象 | 做法 |
|---|---|
| 服务账号 | 每个服务用独立账号跑（nginx 用 www-data，mysql 用 mysql），不用 root 跑服务 |
| 配置文件 | 644（大家能读，只有属主能改） |
| 密钥/证书 | 600（只有自己能读写） |
| 网站目录 | 755（web 服务需要读和进） |
| 脚本 | 755（需要执行） |

# 第五部分：面试怎么讲 D3（60 秒版 + 追问预案）

### 60 秒话术

> "服务器上的账号和权限我按最小权限原则来配。建运维账号时用 `useradd -m -s /bin/bash` 建家目录和 shell，再用 `usermod -aG sudo` 加进 sudo 组——这里 `-a` 不能漏，否则会覆盖原有组。授权后我一定会切到那个账号实测 `sudo whoami` 和 `groups`，确认生效，而不是只在原账号下测试。
>
> 权限方面我理解 rwx 对文件和目录的区别——目录的 x 是能不能 cd 进去，这一点很多人会答错。家目录 Ubuntu 24.04 默认是 750，比老版本的 755 更安全，其他用户完全进不去。
>
> 链接这块我做过实验：硬链接和源文件 inode 号相同，删掉源文件硬链接照样能读；软链接存的是路径，源文件没了它就失效。理解 inode 之后就能解释一个常见故障——删了大文件磁盘空间不释放，通常是有进程还持有已删除文件的句柄，要用 `lsof | grep deleted` 查。"

### 追问预案

| 追问 | 标准答 |
|---|---|
| rwx 对目录是什么意思 | r=能 ls，w=能增删文件，**x=能 cd 进去** |
| 755 怎么算的 | r=4 w=2 x=1；属主 7，属组 5，其他 5 |
| 软硬链接区别 | 硬链接同 inode、删源仍存活、不能跨分区和链目录；软链接存路径、删源失效、可跨分区可链目录 |
| 删了文件磁盘不释放 | 有进程持有已删除文件的句柄 → `lsof \| grep deleted` → 重启进程或用 `> 文件` 清空而非 rm |
| 为什么不用 root 操作 | 最小权限、可追溯、合规要求 |
| usermod -aG 的 -a | append，不加会覆盖用户的附加组 |
| 家目录权限 | Ubuntu 24.04 默认 750（24.04 前是 755） |

# 第六部分：今天踩的坑，价值在哪

| 坑 | 表面是失误 | 实际学到的 |
|---|---|---|
| `su -ops` 缺空格 | 命令报错 | shell 参数解析：横杠后跟字母会被当选项 |
| `sudo - ops` | command not found | `sudo` 后接的是"要执行的命令"，不是用户名 |
| 在 jasper 下测 sudo | 测试结果无效 | **验证要切到目标账号**——测试方法论的严谨性 |
| 手册说 `chmod 755` | 照做反而降低安全 | 教程会过时，要理解"为什么"而不是照抄（24.04 已默认 750） |
| 中文变拼音 | 文件内容是 `yunweishiyan` | 终端环境处理中文易出问题——印证 D1 选 English 是对的 |

**讲坑的正确姿势**（五段式）：现象 → 怎么定位 → 根因 → 怎么解决 → 沉淀了什么习惯。这是运维排查的标准叙事，面试讲一个完整案例比背十个命令有用。

# 附录：D3 命令速查表

| 命令 | 白话解释 |
|---|---|
| `whoami` | 我是谁（当前用户名） |
| `useradd -m -s /bin/bash 名` | 建账号（带家目录、指定 bash） |
| `passwd 名` | 给账号设密码 |
| `usermod -aG 组 名` | 把用户**追加**进组（-a 不能漏） |
| `su - 名` | 切换到该用户并加载其完整环境 |
| `exit` | 退回上一个用户/退出登录 |
| `groups` | 看我在哪些组里 |
| `sudo whoami` | 测试 sudo 是否生效（输出 root 就是成功） |
| `ls -l` | 看详细信息（含权限、属主、大小） |
| `ls -ld 目录` | 只看目录本身的信息（不展开内容） |
| `ls -li` | 看 inode 号（第一列） |
| `chmod 755 文件` | 改权限（r=4 w=2 x=1） |
| `chmod u+x 文件` | 给属主加执行权限 |
| `chown 主:组 文件` | 改属主和属组 |
| `ln 源文件 链接名` | 建**硬**链接（同 inode） |
| `ln -s 源文件 链接名` | 建**软**链接（存路径） |
| `lsof \| grep deleted` | 查"已删除但仍被进程占用"的文件 |
