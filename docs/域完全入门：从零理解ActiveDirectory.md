## 第一章：为什么会有"域"这个东西（从真实痛点讲起）

### 场景一：只有 3 台电脑的小公司（工作组够用）

老板 + 两个员工，一人一台电脑。每台电脑自己管自己的账号（**工作组模式**，Windows 装完默认就是这个）：
- 老板电脑上有账号"老板"
- 员工A电脑上有账号"员工A"
- 员工B电脑上有账号"员工B"

**没问题**——反正每台电脑只有一个用户，账号谁用谁管。

### 场景二：公司扩张到 30 台电脑（工作组开始崩溃）

问题一个接一个：

| 问题 | 描述 |
|---|---|
| **账号满天飞** | 员工A要用打印机电脑？得在打印机电脑上**再建一个员工A**。30 台电脑 × 30 个员工 = 每台电脑建 30 个账号 |
| **密码各不相同** | 员工A在电脑1上密码是 abc123，在电脑2上是 456def——**他自己都记不住** |
| **离职是灾难** | 员工B离职了，他的账号散落在 30 台电脑上，**IT 要一台台去删** |
| **权限失控** | 谁能看工资表？不知道——每台电脑的权限各自为政，没人说得清 |
| **没有统一策略** | 想让所有电脑 5 分钟锁屏？**30 台挨个设置** |

**这就是工作组的死穴：账号散落在每台电脑上，没有一个统一管理的地方。**

### 场景三：域的解法（把账号从电脑里"抽"出来，集中放一个地方）

**域的核心思想只有一句话**：

> **把所有账号、密码、权限，从每台电脑里抽出来，集中存到一台"大脑服务器"上。所有电脑加入这个体系后，登录时都去大脑那里验证。**

这台"大脑服务器"就是**域控制器（DC）**——你今天把 DC01 提升成的那个东西。

**效果对比**：

| 需求 | 工作组 | 域 |
|---|---|---|
| 新员工入职 | 每台电脑挨个建账号 | **建 1 个账号，全网通行** |
| 员工离职 | 30 台电脑挨个删 | **禁用 1 个账号，全网失效** |
| 统一策略（锁屏/密码/桌面） | 每台挨个设置 | **1 条策略全网下发** |
| 新电脑接入 | 各自配账号 | **加进域，自动纳入管理** |

**这就是为什么企业都要用域**——不是技术炫技，是**规模化的必然**。你投的政企驻场岗，公司的内网就是域，你日常干的活（重置密码、解锁账号、加电脑进域）就是在维护这个体系。

## 第三章：核心概念逐个击破（每个都是大白话）

### ① 域控（Domain Controller, DC）——大脑

存着全网的账号密码数据库、负责验证每个登录请求、下发策略的服务器。

- **你的 DC01 就是第一台域控**
- 企业里至少 2 台（DC01 + DC02，数据自动同步，一台挂另一台顶上——**冗余**）
- 域控上跑的**核心服务**：AD DS（账号数据库）+ DNS（域名解析）+ Kerberos（认证服务）

### ② AD DS（Active Directory 域服务）——域的"技术实现"

你在 D9 装的那个"角色"。它包含：
- **AD 数据库**（NTDS.dit 文件，存在 `C:\Windows\NTDS\`）——所有用户、电脑、组的记录都在里面
- **验证服务**（Kerberos）——登录时验密码的就是它
- **LDAP 接口**——其他系统查账号用的协议

**一句话**：AD DS = "域"这个功能的具体软件实现。你说的"装域"就是"装 AD DS 并把它变成域控"。

### ③ 域名 sjzlab.local——域的"门牌号"

- 你起的名字（`sjz` = 石家庄实验室的缩写，`.local` = 内部专用后缀）
- **它同时是 DNS 域名**——所以装域自动装了 DNS
- 域内所有电脑/用户都会注册到这个域名下（如 `DC01.sjzlab.local`、`zhang.san@sjzlab.local`）

> **为什么用 .local 不用 .com**：.local 是保留给内部网络的后缀（不会被公网解析）。企业内网域名用 .local 或自有域名子域（如 ad.company.com）都行——**不能和公网域名冲突**是关键。

### ④ NetBIOS 名 SJZLAB——域的"小名"

`SJZLAB` 是从 sjzlab.local 自动取的**旧式短名**（NetBIOS 协议时代遗留）。登录时 `SJZLAB\zhang.san` 用的是它。**和 sjzlab.local 是同一个域的两种称呼**。

### ⑤ OU（组织单位）——域里的"部门文件夹"

把用户、电脑、组按**部门/职能**归类的容器（你 D10 建的 ops OU 就是"运维部"）。

**OU 的真正价值**：**GPO 链接到 OU 上，精准下发到这个部门**——运维部的策略不影响财务部。

> OU 和"文件夹"的区别：OU 上可以**链接组策略**，普通文件夹不能。这是 OU 存在的核心理由。

### ⑥ 域用户 vs 本地用户（你建 zhang.san 时接触的）

| | 域用户 | 本地用户 |
|---|---|---|
| 存在哪 | 域控的 AD 数据库 | 每台电脑自己（SAM 数据库） |
| 登录范围 | **域内任何电脑** | 只能登自己这台 |
| 谁建的 | 管理员在 AD 里建（一次） | 每台电脑各自建 |
| 典型例子 | zhang.san（你建的） | 你 sv01 上的 jasper（Linux 世界不算，但概念同理） |

**你今天验证过的**：zhang.san 只在 AD 里建了一次，但**在 DC01 上就能登录**——如果明天有一台新电脑加入域，zhang.san **不用再建一遍，直接就能登录**。这就是域用户的价值。

### ⑦ 组（Group）——批量授权的工具

**问题**：100 个员工都要访问文件服务器，你一个个授权？100 遍。

**解法**：建一个组"全体员工"，把 100 人拉进去，**对组授权一次 = 组内所有人都有权限**。

**常用内置组**（DC01 自带）：
- **Domain Admins**（域管理员）：域内最高权限——**进这个组的账号可以管理整个域**（极度谨慎，一般只有 IT 主管）
- **Domain Users**（域用户）：所有普通域用户默认在里面
- 你建 zhang.san 时，它**自动加入了 Domain Users 组**（默认行为）

### ⑧ GPO（组策略对象）——中央下发的"规则包"

你 D10 建的 ops-policy 就是。它是一份配置规则的集合（锁屏、密码复杂度、桌面限制、软件部署……几千条可配），**链接到 OU 或域之后自动应用**。

**GPO 的层级应用顺序（LSDOU）**：
```
Local（本地）→ Site（站点）→ Domain（域）→ OU
                                              ↑ 最后应用，优先级最高
```
**规则：后面的覆盖前面的**。这就是为什么链接到 ops OU 的策略，能精准控制 ops 部门的人。

**GPO 能干什么（几千条设置，常见的）**：
- 密码复杂度、锁屏时间（**安全基线**——等保要求）
- 桌面壁纸统一、隐藏图标（你做的）
- 禁止 U 盘、禁止改 IP（**防病毒扩散**）
- 开机自动装软件（软件分发）
- 映射网络盘符（Z盘=共享文件夹）

### ⑨ DNS——AD 的"电话簿"（AD 命脉）

**AD 强依赖 DNS 的原因**：域内电脑登录时，第一步是问 DNS："**域控在哪？**"（查询 SRV 记录）——DNS 回答"在 192.168.207.10"，电脑才知道找谁验证。

**所以**：
- 装 AD 自动装 DNS（不是可选项）
- 域控的 DNS 必须指向自己（192.168.207.10）
- 全域电脑的 DNS 必须能解析到域控
- **DNS 挂了 = 全员无法登录**（这就是为什么域控上 DNS 服务和 AD 是绑死的）

### ⑩ Kerberos——域内的"验票系统"

你登录成功后，DC 发给你**两张票据（Ticket）**：
- TGT（票据授予票据）：相当于"入场手环"，证明"你已经通过验证"
- 之后访问域内任何资源（文件共享、打印机），出示 TGT 换"具体服务的票"——不用再输密码

**大白话**：进游乐场买一次手环（TGT），玩每个项目出示手环换票——**不用每个项目重新买票（重新输密码）**。

**这就是为什么域内"一次登录，全网通行"**——Kerberos 票据机制在背后默默工作。

### ⑪ DSRM——域控的"备用钥匙"

Directory Services Restore Mode：AD 数据库损坏、域控无法正常启动时，用它进**修复模式**抢救数据库。

**它和 Administrator 密码是两回事**（D9 升域时单独设的那个）。**丢了 DSRM = 域控坏了救不回来**。你设的是 Qwer1234!——已记入你的文档体系。

## 第四章：登录时发生了什么（输入 zhang.san 后的完整旅程）

以你 D10 的验证为例：在 DC01 登录界面输入 `zhang.san` + 密码后：

```
第 1 步：电脑问 DNS
  "sjzlab.local 的域控在哪？"
  DNS 答："192.168.207.10"（DC01）

第 2 步：电脑找 DC01 验证
  "我要用 zhang.san 登录，这是我的密码"
  （通过 Kerberos 协议加密传输）

第 3 步：DC01 查 AD 数据库
  "zhang.san 存在吗？" → 存在（你建的）
  "密码对吗？" → 对（哈希比对）
  "账号被禁用了吗？" → 没有

第 4 步：DC01 发票据
  "验证通过！给你 TGT（入场手环）"
  顺带："你是 ops OU 的成员，ops-policy 的策略对你生效"

第 5 步：加载用户环境
  应用 GPO（桌面图标被隐藏——你亲眼看到的）
  加载用户配置文件
  桌面出现
```

**全程不到 3 秒**，但背后走了这五步。**你看到的"登录成功"是这五步全部通过的结果**——任何一步失败，就是各种登录报错（这也是运维排域登录故障的思路：按这五步逐层查）。

| 机器 | IP | 角色 | 状态 |
|---|---|---|---|
| DC01 | 192.168.207.10 | **域控**（sjzlab.local 的大脑）：AD + DNS + 组策略中枢 | ✅ 运行中 |
| sv01 | 192.168.207.128 | Linux 服务器（W1 交付的，**不在域里**——Linux 有自己的账号体系） | ✅ 运行中 |

**D10.5 加域客户端的意义**：加域之后，你可以在**DC01 的 AD 管理工具里看到这台电脑**（Computers 容器下多一个条目）、用 zhang.san 在它上面登录、对它下发组策略——**域的"统一管理"就从理论变成了现实**。

## 第七章：常见困惑 FAQ

| 困惑 | 解答 |
|---|---|
| 为什么域名是 .local 不是 .com | .local 是**内网保留后缀**（不会和公网冲突）。也有企业用子域（ad.company.com）——**原则：内网域名不能和公网域名重复** |
| DSRM 和管理员密码什么关系 | **两回事**：DSRM 是进修复模式的钥匙（救 AD 数据库用），管理员密码是日常登录用。**两个都要记牢** |
| 域控和 DNS 什么关系 | 域控**必须**有 DNS（AD 靠 DNS 找到域控），所以装域自动装 DNS；但 DNS 服务器不一定是域控（可独立部署） |
| zhang.san 能在 DC01 上装软件吗 | 取决于权限——默认域用户是普通权限（不能装软件），只有 Domain Admins 才能全权管理。**这正是最小权限** |
| 域控坏了会怎样 | 全员可能无法登录（DNS 和验证都挂了）——**所以企业至少两台域控**（数据自动同步） |
| 快照能回滚域控吗 | **能，但要小心**：升域后拍的快照可以回；但如果回滚到升域前，AD 数据库和 DNS 全部消失（你拍的"升域前"快照就是干这个用的——升域搞砸了回到普通服务器重来） |

## 第八章：面试考点汇总（域相关高频题）

| 题目 | 核心答法 |
|---|---|
| 域和工作组的区别 | 账号集中 vs 分散；规模：域适合一切正经企业，工作组 10 台以内凑合 |
| 什么是 AD | 微软的目录服务——集中存储全网账号/电脑/权限的数据库 + 验证服务 |
| 域控的作用 | 存账号、验登录、下发策略、DNS 解析——全网的中央权威 |
| 为什么要两台域控 | 冗余：一台挂了另一台顶上（AD 数据自动同步） |
| 什么是 OU | 域内组织容器，用来分类管理 + 精准下发 GPO |
| 什么是 GPO | 组策略对象——集中配置规则包，链接到 OU/域自动应用（LSDOU 顺序） |
| 登录失败怎么排查 | 按五步：DNS 能解析域控吗 → 网络通吗 → 账号存在吗 → 被锁了吗 → 密码对吗 |
| Kerberos 是什么 | 域内认证协议——票据机制，一次验证全网通行（替代反复输密码） |
